`2026.MovieReview.html` —— 135 部电影长片、平均 3.73 分的年度报告。
单文件、离线可开、无外部依赖；双击就能看，不用联网也不用服务器。

## 二、页面上的几个交互

| 交互 | 说明 |
|---|---|
| **L 键熄灯** | 电脑端按 `L`，整页压暗、只留鼠标附近一圈暖光；再按一次 `L` 或 `Esc` 恢复。手机 / 平板不注册这个键，页脚那行提示也会自动隐藏 |
| **缩放不跑位** | 拖动窗口宽度时，页面停在你正在读的那一块（实测 1280 → 560），不会一下跳到别的章节 |
| **三卡 / 三格强制同行** | 三大电影节卡，以及「新片数量 / 我的均分 / 五星部数」三格，任何宽度都是同一行三列，不折行、不外溢 |
| **电影节标题自适应** | 标题永远带「电影节」三个字；放不下时三张按**同一字号**一起缩，全屏仍是 19px |
| **年代分布柱图** | 九个年代列严格等分，窄屏只缩标签、不动柱子，柱底永远同一基线 |

页脚那行小字是：`电脑端按 L 键可关灯，再按一次即亮起`，只在带鼠标的设备上显示。

## 三、压缩窗口宽度：变的是横向，纵向不动

这一版所有窄屏适配都遵守同一条规则：**窗口拖窄只压缩横向（列宽、字号、间距、内边距），纵向尺寸不跟着按比例缩**。

| 纵向固定项 | 值 | 说明 |
|---|---|---|
| 年代柱图区高度 | `240px`，写死 | 从 280 到 1920 都一样，柱子再高也不会把这块撑大或压扁 |
| 柱子高度 | 百分比 | 按当年部数占比算，只有横向宽度会变（最宽 58px 封顶）|
| 柱底基线 | 永远齐 | 九个年代列的柱底在同一条线上，不会有一根冒出来 |
| 同一行三张卡 / 三格 | 永远等高 | 三张电影节卡、三格 KPI 高度一致，不会一张高一张矮 |
| 卡片内容 | 不裁、不折行 | 只有三大电影节标题会缩字号（见下）；极端窄（< 300px）时标题末尾可能被 `overflow:hidden` 吃掉一两像素 |

变的主要是这些：九列之间的 `gap`、标签字号、卡片内边距、破折号与角标字号。

> 说明一下「高度不变」的边界：卡片与 KPI 的**绝对高度**会跟着字号档走阶梯（同一档内完全恒定，跨档才有几像素到二十像素的变化，因为字号和内边距一起降了）；
> 而**同一行的三张卡、三格**在任何一个宽度上都严格等高，柱图区则永远是 240px 不动。

### 三大电影节标题（唯一会缩字号的地方）

标题永远显示全名（含「电影节」三个字），放不下时**三张按同一字号一起缩**，由 `festFit()` 在渲染后算出来：

| 宽度 | 标题字号 |
|---|---|
| ≥ 740 | `19px`（CSS 基准，全屏也保持这个）|
| 560 | `15.8px` |
| 420 | `12.4px` |
| 375 | `12.6px` |
| 300 | `8.4px` |
| 280 | `8.2px` |

> 字号是按可用宽度算出来的连续值，不是写死的档位，所以档位边界（400 / 420 / 560 附近）会有一两像素的跳动，属正常。

### 改这些数值时动哪里

文件里三块注释是入口，按名字搜就能定位：

```
/* ---------- 三大电影节卡片：任何宽度都保持三列一行，窄屏逐级缩小 ---------- */
/* ---------- 2026 专题 KPI 三格：同样任何宽度都三列一行，窄屏逐级缩小 ---------- */
/* ---------- 年代分布柱图：九列严格等分，窄屏标签缩字保持单行 ---------- */
```

另外 `§16 响应式` 那段是全局断点（980 / 620），先看再改。

### 调完怎么验证

拿基准宽度扫一遍：280 → 2560，步长 10，共 229 档，每档查六项——柱图有没有溢出、柱子有没有越过边框、标签有没有折成两行、标签有没有宽过本列、九列宽度是否一致、柱底是否同一基线。当前版本是 **bad = 0**（六项全过）。改档位后重跑一遍，别只看某一个宽度“看起来还行”。

把图片放进 `海报\`，文件名用「《片名》海报」：


## 五、年末要补的数据

用记事本或 VS Code 打开 `2026.MovieReview.html`，搜索：

```
===== 年末只需要改这里
```

下面是一个 `CONFIG` 对象，两处要改。

**1）`festivals` —— 三大电影节入选数**

```json
{ "name": "柏林", "en": "BERLINALE", "total": 5,
  "units": [ { "n": "主竞赛单元", "v": 3 },
             { "n": "全景单元", "v": 2 } ] }
```

- 卡序固定 **柏林 → 戛纳 → 威尼斯**，右上角角标固定显示 `Feb` / `May` / `Sep`（各自举办月份），不用你填
- `units` 按现在写好的单元逐条填 `v`：柏林 2 项（主竞赛、全景），戛纳 3 项（主竞赛、导演双周、影评人周），威尼斯 1 项（主竞赛）
- 把 `null` 换成数字即可，页面会自动把「年末补录」换成「已确认」

**2）`top5` —— 年度五佳**

第 1 名已定为《可能的爱》。其余四部改 `t`（片名）与 `quote`（一句话），
`runtime` 填分钟数（不填显示「—」）。片名要和豆瓣条目一致，才会自动带出导演、主演。

### 数字会自己变吗？

会。正文数字不是手写的，是从豆瓣导出的 `2026.Douban286590474.xlsx` **算出来再注入 `DATA` 的**：

- 封面部数、评分、字数、星级分布
- 逐月柱状图、24 小时分布、年代分布
- 导演榜、出品地排行、系列进度
- 热词与标签
- 2026 新片专题的全部统计
- 连各章节导语里的数字都是自动填的（如「希区柯克一个人贡献了 6 部」「美国 39 部（28.9%）」）

流程是：**换新 xlsx → 跑 `douban_v3/rebuild.py` 重算 → 页面全部更新**，不需要手动改任何数字。

不会自动变的只有三样：

| 项目 | 说明 |
|---|---|
| 电影节数字 | `CONFIG.festivals`，年末给数，填进去 |
| 年度五佳 | `CONFIG.top5`，年末给片单，填进去 |
| 海报图片 | 放进 `海报\`，文件名 `《片名》海报.jpg` |

## 八、改这个文件时的几条底线

- **保持 UTF-8 带 BOM**（Windows 记事本另存时选「UTF-8」，别选「UTF-8 无 BOM」以外的奇怪编码），否则中文标签会乱码
- **别删 `.stage` / `#festGrid` / `#y26kpis` 这几个容器和它们的 id**，JS 往里写内容，删了就是空白
- **CSS 颜色走变量**（`var(--gold)` 之类），不要直接写死色值，换主题时才不用满地找
- **内容块默认 `opacity:0`**，靠 `IntersectionObserver` 加 `.in` 显示；手动截图或打印前可以临时覆盖 `.reveal{opacity:1!important;transform:none!important}`
- **别动 `2025\` 那边**：2025 是老版式，没有海报位、没有灯效，互不影响
